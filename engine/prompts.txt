Let's write the code for this blog. First version would be very simple.

Repository structure looks like this:
prompted-blog/
├── .git/
├── engine
│   └── prompts.txt
├── generate.py
├── instructions.txt
└── posts
    └── 2025-07-27
        ├── output.md
        └── prompts.txt

There is only one post in posts directory. Assume that the latest post is what will be displayed in blog homepage. Assume that git dot dir will exist in this dir, so static files can be generated by using git commands following each post in this format as deeply as needed. Each file will be tracked only through diff. prompts.txt contains the most recent version of user prompts for the post, instructions.txt is the latest version of the iteratively developed custom instructions for the project as a whole, output.md is the aggregated output from the LLM. We will work on only one paragraph at a time, finish that, append the latest content to the start of chat and restart chat again. This is to avoid context window issues.

The blog engine would be where every page will be posted like a note and on opening that note, it'll display the full replay with the latest version as the current page and a tiny scroll button at the bottom which can horizontally scroll as a revision of the prompts which resulted in a specific blog content with diff. We can start building a way to emit html files from markdowns and jsons from git diff for the relevant files. When a page is opened, it only displays the rendered view but it will have "show prompt history" button on the left, which, when clicked animates moving the rendered page view to the right, adding a name output.md at the top. Then, two more views are added, one for instructions.txt and one for prompts.txt. The diff for the latest version is rendered on both the text files. Markdown is shown as-is.

With the version mode enabled (which can be URL query parameter), the scroll button and diff views come into existence. This is where dynamic loading would help - we want to be able to load the json files one by one starting with the last to the latest and going all the way to the first in reverse in a progressive load, animating the progress below in a line or series of dots (clickable) in the horizontal scroller area.
